# 团队科研 Wiki 与 AI 工作规范

本仓库是一个轻量的团队科研 Wiki。它保存论文原文、已有讲解、项目资料和实验记录，并提供一套跨 AI 平台的工作规范，帮助成员用自己的 AI 工具整理和查询资料。

## 项目定位

本项目的核心是 **GitHub Markdown Wiki + AI 工作规范**，不是 RAG 服务、知识图谱数据库或共享聊天机器人。

- GitHub 保存和同步团队资料；
- Markdown 文件是可长期阅读、修改和追踪的知识记录；
- `skills/` 提供可选的结构化 AI 工作规范；
- `PORTABLE_WORKFLOW.md` 提供不依赖具体平台的通用提示词；
- `optional-tools/` 只存放可选的扫描、搜索、去重和安装脚本。

当前不需要部署服务器。每位成员使用自己的 AI 工具，并按照同一套记录规范把结果同步到 GitHub。

## 目录结构

- `00_index/`：论文目录、主题标签、更新日志和术语表
- `01_papers/`：论文原文与讲解笔记
- `02_projects/`：项目说明和研究决策
- `03_experiments/`：实验记录、结果和失败分析
- `04_code/`：代码、环境和 API 说明
- `05_datasets/`：数据集卡片和预处理说明
- `06_prompts/`：可复用提示词和评测样例
- `07_faq/`：团队确认过的常见问题
- `99_archive/`：需要保留的旧版本
- `skills/`：可选的 AI 工作规范模块
- `PORTABLE_WORKFLOW.md`：跨平台通用工作流
- `optional-tools/`：可选脚本，不是日常使用的必需部分

## 推荐使用流程

### 1. 阅读论文并做笔记

成员使用自己熟悉的 AI 工具阅读论文，按照统一记录包含以下内容：

- 标题、作者、年份、DOI；
- 研究问题和数据来源；
- 方法、主要结果和图表；
- 局限性、与团队项目的关系；
- 原文路径、贡献者和日期。

### 2. 用自然语言加入知识库

在支持文件上传的 AI 工具中上传论文和讲解，然后输入：

```text
把我刚上传的论文和已有讲解加入团队科研 Wiki，保存到合适的主题目录，更新 00_index/catalog.md 和 00_index/update-log.md，不需要重新分析论文。
```

AI 应保留原文和已有讲解，不要用一份泛泛的摘要覆盖团队记录。

### 3. 同步到 GitHub

检查修改内容后提交并 Push。只有同步到 GitHub，其他成员才能看到。上传到聊天窗口但没有写入仓库的附件不会自动成为团队资料。

### 4. 按主题查找和问答

可以直接提问：

```text
查找团队科研 Wiki 中与单细胞扰动预测相关的论文，按主题列出原文、讲解、年份和贡献者。
```

AI 应先读取 `00_index/catalog.md` 和相关 Markdown 笔记，再按需打开原文。默认不要一次加载整个仓库。

### 5. 分级加载

1. 先读目录、标签和更新日志；
2. 再读最多 5 篇相关 Markdown 记录；
3. 只有需要核对时才打开最多 3 篇原文的相关页码；
4. 回答时引用实际读取过的文件；
5. 没有证据时明确说明 Wiki 中没有找到。

## Skill 与 Wiki 的关系

Skill 是 AI 的工作规范，Wiki 是团队实际积累的内容。Skill 可以规定如何命名文件、提取元数据、更新目录和引用来源，但不会代替论文、笔记或 GitHub 仓库。

- 支持 Agent Skills 的平台：使用 `skills/` 中对应的 `SKILL.md`；
- 支持系统提示词的 AI：使用 `PORTABLE_WORKFLOW.md`；
- 只支持普通聊天的 AI：提供 `PORTABLE_WORKFLOW.md` 和相关 Markdown 记录。

不同 AI 平台的安装方式可能不同，但目录结构、记录模板和问答原则保持一致。

## 可选工具

`optional-tools/` 中的脚本用于需要时的维护：

- `scan_knowledge_base.py`：扫描新文件；
- `search_papers.py`：搜索 Markdown、文本和 BibTeX；
- `check_duplicates.py`：检查哈希重复和 DOI 冲突；
- `install-skills.ps1`：在支持该目录规范的环境中批量安装工作规范。

这些工具不是使用 Wiki 的前提。没有脚本时，也可以直接通过 GitHub 网页、Markdown 模板和 AI 工作规范维护资料。

## 当前边界

本项目不提供服务器端全文 RAG、向量数据库、知识图谱或共享网页问答。若未来资料规模需要自动召回，再考虑增加索引服务；届时 GitHub Wiki 仍可作为原始资料来源。

## 文件与隐私

- 私有仓库用于团队内部资料；
- 不提交密码、Token、患者隐私或未经授权的数据；
- 单个文件过大时先评估 Git LFS 或其他存储；
- 不随意删除原文，旧版本放入 `99_archive/`；
- 重要结论必须保留来源文件、页码、DOI 或实验记录。
